Обробка "Універсальний обмін даними у форматі XML" призначена для завантаження і вивантаження даних у файл з будь-якої конфігурації, реалізованої на платформі

Обробка має чотири закладки

Вивантаження даних

Для здійснення вивантаження даних необхідно вказати ім'я файлу, до якого здійснюватиметься вивантаження даних, і вибрати файл правил обміну. Правила обміну для будь-яких конфігурацій можуть бути налаштовані в спеціалізованій конфігурації "Конвертація даних, редакція 2".

Для вивантаження документів і записів незалежних періодичних регістрів відомостей необхідно вказати період - "Дату початку" і "Дату закінчення". Результуючий файл з вивантаженими даними може бути стиснутий.

На закладці "Правила вивантаження даних" можна вибрати ті типи об'єктів, які мають вивантажуватися, налаштувати відбори для вибірки об'єктів, або вказати вузол обміну даними, для якого потрібно вивантажувати дані.

На закладці "Параметри вивантаження" можна вказати додаткові параметри вивантаження даних.

На закладці "Коментар" можна написати довільний текст-коментар, що включається у файл обміну.

Завантаження даних

Для здійснення завантаження даних необхідно вказати ім'я файлу, з якого буде здійснюватися завантаження даних.

Є можливість налаштувати завантаження даних у транзакції. Для цього необхідно звести прапорець "Використовувати транзакції" і вказати кількість елементів в одній транзакції під час завантаження.

"Завантажувати дані в режимі обміну (ОбменДанными.Загрузка = Истина)" - якщо прапор встановлений, то завантаження об'єктів виконуватиметься зі встановленою ознакою завантаження. Це означає, що під час запису об'єктів у базу даних буде відключено всі платформні та прикладні перевірки. Виняток становлять документи, які записуються в режимі проведення або скасування проведення. Проведення і скасування проведення документа виконується завжди без встановлення режиму завантаження, тобто перевірки будуть виконуватися.

Додаткові настройки

Закладка служить для детальної настройки вивантаження і завантаження даних.

"Режим налагодження" - прапор для завдання режиму налагодження обміну. Якщо цей прапор установлено, то процес обміну даними не буде зупинено в разі виникнення будь-якої помилки. Обмін завершиться до кінця з виведенням налагоджувальних повідомлень у файл протоколу обміну. Цей режим рекомендується використовувати під час налагодження правил обміну.

"Виведення інформаційних повідомлень у вікно повідомлень" - якщо прапор встановлений, то у вікно повідомлень виводитиметься протокол процесу обміну даними.

"Кількість оброблених об'єктів для оновлення статусу" - параметр слугує для визначення кількості оброблених елементів перед зміною рядка стан завантаження/вивантаження

"Настройка вивантаження даних" - дають змогу визначити кількість елементів, що обробляються в одній транзакції під час вивантаження даних, вивантажувати й обробляти тільки ті об'єкти, на які є права доступу, налаштувати тип зміни реєстрації для вивантажених об'єктів через плани обміну.

"Використовувати оптимізований формат для обміну даними (V8 - V8, версія обробки не нижче 2.0.18)" - оптимізований формат повідомлення обміну передбачає наявність вузла "ИнформацияОТипахДанных" у заголовку повідомлення, у який вивантажується інформація про типи даних. Це дає змогу прискорити процес завантаження даних.

"Використовувати транзакції під час вивантаження для планів обміну" - прапор визначає режим використання транзакцій під час вивантаження даних під час вибірки змін на вузлах планів обміну. Якщо прапор встановлено, то вивантаження даних буде виконуватися в транзакції.

"Кількість елементів у транзакції" - визначає максимальну кількість елементів даних, які поміщаються в повідомлення в рамках однієї транзакції бази даних. Якщо значення параметра дорівнює 0 (значення за замовчуванням), то всі дані поміщаються в рамках однієї транзакції. Такий режим є рекомендованим, оскільки гарантує узгодженість даних, що поміщаються в повідомлення. Але при створенні повідомлення в багатокористувацькому режимі можуть бути конфлікти блокувань між транзакцією, в якій дані поміщаються в повідомлення, і транзакціями, що виконуються іншими користувачами. Для зниження ймовірності виникнення таких конфліктів можна задати значення цього параметра, відмінне від значення за замовчуванням. Що менше значення параметра, то менша ймовірність конфлікту блокувань, але вища ймовірність поміщення в повідомлення неузгоджених даних.

"Вивантажувати об'єкти, на які є права доступу" - якщо прапор встановлений, то вибірка об'єктів інформаційної бази буде виконуватися з урахуванням прав доступу поточного користувача програми. Це передбачає використання літерала "ДОЗВОЛЕНІ" в тексті запиту для вибірки даних.

"Автоматично видаляти неприпустимі символи з рядків для запису в XML" - якщо прапор установлено, то під час запису даних у повідомлення обміну неприпустимі символи буде видалено. Символи перевіряються на відповідність рекомендації XML 1.0.

"Зміни реєстрації для вузлів обміну після вивантаження" - поле визначає режим роботи з реєстрацією змін даних після завершення вивантаження даних. Можливі значення:

  • Не видаляти реєстрацію - після вивантаження даних реєстрація змін на вузлі видалена не буде.
  • Повністю видалити реєстрацію для вузла обміну - після вивантаження даних реєстрацію змін на вузлі буде повністю видалено.
  • Видалити реєстрацію тільки для вивантажених метаданих - після вивантаження даних реєстрацію змін на вузлі буде видалено тільки для об'єктів метаданих, які були вказані до вивантаження.


"Протокол обміну" - дає змогу налаштувати виведення інформаційних повідомлень у вікно повідомлень, ведення і запис в окремий файл протоколу обміну.

"Ім'я файлу, протоколу обміну" - ім'я файлу для виведення протоколу процесу обміну даними.

"Протокол завантаження (для COM-з'єднання)" - ім'я файлу для виведення протоколу процесу обміну даними в базі-приймачі під час обміну через COM-з'єднання. Важливо: шлях до файлу має бути доступним з комп'ютера, на якому встановлено базу-приймач.

"Дописувати дані в протокол обміну" - якщо прапор встановлений, то вміст файлу протоколу обміну зберігається, якщо файл протоколу вже існує.

"Виведення в протокол інформаційних повідомлень" - якщо прапор встановлений, то в протокол обміну будуть виводитися повідомлення інформативного характеру, крім повідомлень про помилки обміну.

"Відкривати файли протоколів обміну після виконання операцій" - якщо прапор встановлений, то після виконання обміну даними файли протоколів обміну будуть автоматично відкриті для перегляду.

Видалення даних

Закладка потрібна тільки для розробників правил обміну. Дозволяє видаляти з інформаційної бази довільні об'єкти.

Налагодження вивантаження і завантаження даних

Обробка дає змогу здійснювати налагодження обробників подій і генерувати модуль налагодження з файлу-правил або файлу-даних.

Увімкнення режиму налагодження обробників вивантаження проводиться на закладці "Вивантаження даних" установкою прапорця "Режим налагодження обробників вивантаження". Відповідно, на закладці "Завантаження даних" увімкнення режиму налагодження завантаження здійснюється встановленням прапорця "Режим налагодження обробників завантаження".

Після встановлення режиму налагодження обробників стане доступною кнопка настройки налагодження. Після натискання на цю кнопку відкриється вікно настройки.

Настройка налагодження обробників виконується в чотири кроки:

Крок 1: Вибір режиму налагодження алгоритмів


На першому кроці необхідно визначитися з режимом налагодження алгоритмів:

  • Без налагодження алгоритмів
  • Викликати алгоритми як процедури
  • Підставляти код алгоритмів за місцем виклику

Перший режим зручно використовувати, коли ми точно знаємо, що помилка в обробнику не пов'язана з кодом будь-якого алгоритму. У цьому режимі код алгоритмів не вивантажується в модуль налагодження. Алгоритми виконуються в контексті оператора "Виконати()" і їхній код недоступний для налагодження.

Другий режим необхідно використовувати в тих випадках, коли помилка знаходиться в коді алгоритму. У разі встановлення цього режиму алгоритми будуть вивантажені як окремі процедури. У момент виклику алгоритму з будь-якого обробника відбувається звернення до відповідної процедури обробки. Цей режим зручно використовувати, коли для передачі параметрів в алгоритми використовується глобальна змінна "Параметри". Обмеження використання цього режиму в тому, що під час налагодження в алгоритмі недоступні локальні змінні обробника, з якого він викликається.

Третій режим налагодження використовується, як і в другому випадку, під час налагодження коду алгоритмів і в тих випадках, за яких другий режим налагодження не підходить. При встановленні цього режиму алгоритми будуть вивантажені як інтегрований код в обробниках. Тобто замість оператора виклику алгоритму вставляється повний код алгоритму з урахуванням вкладених алгоритмів. У цьому режимі немає обмежень на використання локальних змінних обробника, однак є обмеження під час налагодження алгоритмів з рекурсивним викликом.

Крок 2: Формування модуля налагодження


На другому кроці необхідно зробити вивантаження обробників натисканням на кнопку "Сформувати модуль налагодження вивантаження (завантаження)". Сформовані обробники та алгоритми будуть виведені в окреме вікно для перегляду. Вміст модуля налагодження необхідно скопіювати в буфер обміну натисканням на кнопку "Копіювати в буфер обміну".

Крок 3: Створення зовнішньої обробки


На цьому кроці необхідно запустити конфігуратор і створити нову зовнішню обробку. У модуль обробки необхідно вставити вміст буфера обміну (модуль налагодження) і зберегти обробку під будь-яким ім'ям.

Крок 4: Підключення зовнішньої обробки


На четвертому, завершальному кроці, треба вказати ім'я файлу зовнішньої обробки в полі введення. При цьому програма виконує перевірку за часом створення (оновлення) файлу обробки. Якщо обробка має більш ранню версію, ніж версія файлу модуля налагодження, то буде виведено попередження, і форма настройки закрита не буде.

Примітка: Можливість налагодження глобального обробника конвертації "Після завантаження правил обміну" не підтримується.
